# Accepted session SPLIT design

The user wants a central queue that ranks whole sessions using the accepted remaining oracle timeline, retains native batching, and finishes each admitted request before reprioritizing. Use one largest-remaining replica and seven smallest-remaining replicas in the eight-B200, cache-off, four-second-arrival study. Compare five paired seeds against JSQ/FCFS and save all plotting data.

## Synthesis decision

Base is Candidate Astra's cluster-owned central gateway and optional native Phase 2 admission source. Both candidates independently chose this boundary and rejected gateway push/credits and a replacement cluster batch builder. On rubric criteria (central pull, causal/accounting correctness, KV nonpreemption, ownership, evaluation), root scores Astra 3/2/2/2/3 and Sol 3/2/1/2/3. Astra accounts for GPT-OSS bounded sequence state and uses logical KV promises without changing physical usage. Sol's physical preallocation would alter native usage measurements and needs broader allocator changes.

Graft Sol's single ready map with deterministic O(ready sessions) min/max selection. At most 2,385 sessions exist in this workload; dual indexed heaps add synchronization obligations without measured need. Graft its explicit failed-admission and zero-reservation-leak tests. Reject its extra CentralAdmissionGateway/Host interfaces because cluster-owned integration avoids expanding the public gateway protocol.

The configured panel was reduced to Astra and Sol when the host rejected further threads; no close-agent tool exists. A separate cross-judge could not be spawned. Root read both full candidates and compared the rubric. Sol will review the implementation independently. No human approval gate applies.

## Narrow implementation contract

1. Policy name `session-split`, strict `remaining_manifest` parameter, existing research-router selection and audit flags. Add a narrow audit-writer interface in the command constructor where the existing concrete gateway return prevents a second implementation. Keep existing branches unchanged.
2. Keep central ownership and SPLIT state in dedicated files, preferably `sim/cluster/session_split*.go`; avoid generic order interfaces and a separate policy package unless they remove actual coupling. Native `sim.AdmissionSource` is generic because the batcher must not know sessions or SPLIT. New study is `research/session_split`.
3. Source offers a request while it remains central. Commit only after successful first native KV allocation, before native newly-scheduled accounting. Commit must be infallible after prior validation. Existing token, sequence, chunking and continuation rules remain authoritative. Failed admission leaves ownership and accounting unchanged. Highest-priority candidate blocks this instance if it cannot fit; other instances may admit it. No packing-based priority bypass.
4. Charge unchanged kernel preparation once using validated homogeneous engines; establish purity from source. Preserve original causal ArrivalTime. Retain each endpoint's configured native renderer. Select a preparation endpoint round-robin in arrival order, independently of eventual GPU assignment; admit to that endpoint's renderer after router latency, or use the uncontended overhead when rendering is disabled. Publish readiness only after preparation finishes. At GPU commit register metrics, input count, assignment, routing and in-flight state exactly once without injecting another arrival. Use a small shared pure normalization/servability helper if necessary; do not duplicate native guards or refactor unrelated paths.
5. Initial research mode rejects unsupported configurations and request features clearly. Cache reuse, offload, speculation, adapters, P/D, heterogeneous/DP endpoint layouts, autoscaling and competing research schedulers are out of scope. Reject nonzero request deadlines instead of implementing new pending timeout accounting. Require complete-drain semi-closed studies; no need to add truncated-horizon metrics in this task. Preserve all old mode behavior. Allow small homogeneous clusters for tests and reuse; only the experiment fixes eight replicas. Replica 0 is the one largest-first endpoint.
6. Ready state is a single owner map; immutable request key uses saved remaining value. Ties ascend causal arrival then stable request ID (same rule in both directions; reverse remaining only). Use explicit runtime session membership, not parsing escaped IDs. Manifest and runtime validate serial session turns. No waiting-time decrement.
7. Publish completion at the reported future timestamp, not callback invocation. Same-time successor arrival must pass after terminal publication, including zero preparation time. Wake only via existing scheduleStepBy/busyUntil machinery; no empty-step polling or phantom capacity. Source-aware early return and next-step logic keep drained engines wakeable.
8. Strict nonpreemption uses logical full-lifecycle KV promises in the single-tier store. Bound with InputLen + normalized MaxOutputLen, including full-attention blocks, bounded SequenceState peak and native admission gate. Keep physical allocations and usage/pricing unchanged. Commit promise only on successful allocation, release on native release. Verify peak bound against kernel/state behavior and tight-capacity tests. Source mode must fail loudly on any native eviction or allocation failure; guards diagnose broken guarantees rather than replace them.
9. Audit preparation/readiness, successful claim, completion, request/session/key, instance role, queue count, times and batch/capacity evidence. An independent replay of ready and claim events must verify exact minimum/maximum choice, one claim/request, placement, nonnegative central wait and zero preemption. Claim should coincide with native scheduling time.
10. Oracle builder uses the saved session class manifest's selected reference_run, and that SAME run's session completion minus each request arrival. Verify 58,741 exact requests, 2,385 sessions, first-size identity, positivity, monotonicity and explicit predecessor completion dependencies. Freeze source hashes. Reference label stays best observed isolated-family elapsed time, including sibling contention and tool delays.
11. Do not modify frozen `research/semiclosed/*.py`, `research/policy_study` helpers or old outputs. Adapt a JSQ preparation plan as the reservation runner does. Freeze one new binary. Run both conditions for seeds42-46, simulator seed42. Reproduce old JSQ outputs exactly (only catalog.path normalization). Full totals are in grounding.md.
12. Save raw workload/metrics/audits, per-session and per-family elapsed makespan and slowdown, per-run mean/p50/p99, aggregate median/range, paired seed percent changes and paired object rows. No extra policy sweep. Intended output `research/outputs/mega-session-split-4s`; report `research/writeups/mega-session-split-4s/README.md`.

## Reconciled implementation findings

- Empty repeated native KV release remains idempotent, matching the existing store. The required guarantees are no negative or leaked promises, no live physical occupancy without its promise, and exact queue/session terminal accounting. There is no requirement to panic on a harmless repeated empty cleanup.
- The actual CLI smoke test revealed that the frozen study inherits one renderer worker per replica from the CLI default. The initial renderer rejection would make the real experiment unusable. The central path therefore retains all eight native one-worker preparation endpoints, with deterministic round-robin ingress independent of GPU claims. This differs from JSQ's coupling between preparation endpoint and eventual GPU; disclose that architectural difference and quantify preparation waiting. Do not change the baseline or silently disable preparation contention. Audit preparation endpoint, service, wait, and exactly-once rendered count, and exercise a contended burst fixture.
